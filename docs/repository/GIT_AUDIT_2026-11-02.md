# CV3DCJP Git and repository audit — 2026-11-02

**Repository:** `Hyperbog/CV3DCJP`. **Authoritative working branch:** `main`.
**Scope:** GitHub remote refs, open/merged pull requests, tracked main-tree layout, source preservation, CI configuration, and ROM-related public-content policy. No local Windows working tree or private ROM was modified by repository cleanup.

## Verified Git findings

- Initially **15 remote branches**: `main`, **13 historical merged-PR branches**, and one collision translation branch (PR #19).
- PRs **#1, #4–#11, #14, #15, #17, #18** were already merged. Their branch refs remained because GitHub repository setting `delete_branch_on_merge` was **false**.
- The historical branch tips are not necessarily ancestors of `main` because earlier PRs used squash or rebased merges; Git comparison alone reports divergence. Merge records establish *PR merge status*, not that every intermediate private/branch-only commit is an exact ancestor of `main`.
- PR **#19** passed GitHub repository-policy CI, was reviewed for directory placement, and was **squash-merged** into `main` at `c2bda92d5447388147019bee54d12c840109b671`.
- `docs/repository/merged-branch-inventory.json` records the 14 branch names, exact *pre-deletion* SHA-1s, and associated merged PR numbers. The branch-pruning script verifies them again immediately before any deletion.
- **Remote branch refs have not been deleted by this GitHub audit:** the connected GitHub actions support merging and file edits but do not expose a branch deletion action. The cleanup script has a safe dry-run mode and requires explicit `-Execute` with GitHub push rights.

The active tracked tree is organized under `.github/`, `data/`, `docs/`, `legacy/`, `src/`, `tests/`, and `tools/`. **Documentation correction:** `docs/REPOSITORY_LAYOUT.md`, `README.md`, and `CONTRIBUTING.md` no longer describe `src/` as unpopulated or require a new permanent branch per subsystem. `tools/git/` contains guarded repository-maintenance tooling; `docs/repository/` contains audit records.

## Tests and limitations

- GitHub workflow `repository-checks.yml` runs Windows and Linux Python repository-policy tests. It is **not** a ROM-matched live gameplay, widescreen, or audio parity test.
- The C11 collision module builds and passes a ROM-free API smoke test locally. Its physical-code ledger validates against the authenticated Japanese ROM separately; **979 native-implemented code bytes, zero formally retired**.
- The pipeline is supplemented with a ROM-free Linux C11 collision compile-and-run smoke job so a broken canonical `Collision.c` is caught by CI.
- A complete live Windows build, original launcher preservation, independent enemy/physics integration, timing, and widescreen correctness remain separate unfinished acceptance requirements.
- The current issues #2, #3, #12, #13, and #16 remain open. No issue was closed without verifying its own acceptance conditions.
- This audit does not establish that every historical branch-only commit was byte-identical to the squashed PR merge. Their branch tip SHAs are recorded before deleting the obsolete branch *names*. GitHub merged PR records preserve change history and review context.

## Single-branch operating policy

1. **`main` is the only permanent development branch.** Maintain canonical system files (`src/collision/Collision.c`, future `src/<system>/...`) and a cumulative ROM-byte ledger.
2. No versioned feature branches left indefinitely. If an isolated PR branch is temporarily necessary, merge the reviewed change, verify `main`, and delete the branch promptly.
3. Do not merge code into the live game simply because a translation compiled or passed synthetic tests. Partial native modules can be tracked on `main` but must remain disconnected from runtime until behavior, timing, and integration proof is complete.
4. Never rewrite protected historical source or remove legacy files solely because a directory name includes `legacy`, `diag`, or a historical phase. Remove only with dependency inventory and tests.
5. No original ROM, ripped copyrighted game assets, saved states, traces, proprietary frame captures, or generated binaries in Git.

## Remote branch cleanup

From a local checkout with working `origin` credentials:

```powershell
& 'C:\NESDev\CV3DCJP-Repo\tools\git\Prune-Merged-Branches.ps1'                    # inspect only
& 'C:\NESDev\CV3DCJP-Repo\tools\git\Prune-Merged-Branches.ps1' -Execute          # deletes SHA-verified merged refs
```

The script refuses any changed branch tip, unmatched PR, unknown remote, unverified PR merge, or attempt to delete `main`; uses `--force-with-lease` with the expected exact SHA. Branch deletion affects refs, **not** the preserved `main` merge commits or recorded PR history. Re-run the dry run after any skipped record and investigate before retrying.
