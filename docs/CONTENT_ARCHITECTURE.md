# Content architecture — ROM-authoritative release design (v1)

**Status:** First ROM extraction has completed for Japanese internal stage/area/room selectors, 135 layouts references, 15 metatile groups and all 128 KiB of physical CHR patterns. This is **not** full gameplay, audio or independent Stage 0 graphics parity.

## Final-release organization

```text
CV3DCJP/
├── src/                         # Engine code, not ROM content
│   └── ...                      # World, camera, renderer, gameplay, audio, platform
├── data/
│   ├── schemas/                 # Versioned public contracts (safe to track)
│   └── generated/               # PRIVATE, ignored owner-local compiled content
│       └── jp-rom-content-v1/
│           ├── source/rom-index.json
│           ├── levels/
│           │   ├── index.json
│           │   └── stage-00/
│           │       ├── stage.json
│           │       ├── area-00/room-00.json
│           │       └── area-01/room-00.json
│           ├── graphics/
│           │   ├── chr-index.json
│           │   ├── chr-patterns.2bpp
│           │   └── metatiles/group-00.json
│           ├── audio/index.json
│           └── gameplay/index.json
├── tools/extract/               # Authenticated ROM -> content compiler
├── tests/                       # Contract, reference and parity gates
└── legacy/rom-backed/           # Protected working original-game baseline
```

All 15 ROM-internal stage selector directories are generated by the current exporter: `stage-00` through `stage-14`. A **stage index is not necessarily a linear player-facing Level 1, 2, 3**: Castle­vania III is branched. That display/order mapping must be evidenced by original game transitions.

## Why levels contain references rather than assets

A room file stores (a) source ROM offset and identifier, (b) room-local screen sections and metatile indices, (c) reference to a shared group of 4×4 CHR-tile definitions, (d) original CHR bank selector bytes. The tile patterns, metatile definitions and raw attribute bytes live once under `graphics/`. This prevents duplication and allows graphics upgrades without altering room layout.

A room's **global world origin, connections, collision semantics and runtime palette phase remain unresolved** until ROM transition/state evidence proves each value. An unresolved entry MUST NOT be given a fabricated default during native rendering. The reference ROM-backed mode remains functional independently.

## Audio and gameplay boundaries

`audio/` will contain ROM-proven song/SFX sequences, instrument and channel definitions, event triggers and 2A03/VRC6 timing. Audio register traces and the PRG alone do not prove where a song begins or how it should be represented. The current audio catalog explicitly has no decoded entries.

`gameplay/` will contain ROM-proven object definitions, movement/collision tables, HP, item/drop rules, enemy AI, progression, selectors, and state transitions. Live CPU/RAM/ROM evidence must accompany each decoded rule. The current gameplay catalog explicitly has no decoded entries.

Audio and gameplay logic should be **separate engine systems**, but level content may reference validated identifiers in these catalogs.

## Compilation and distribution

The user supplies the authenticated Japanese ROM locally. The deterministic extractor generates **private** original content under ignored `data/generated/`. The final game engine consumes the versioned content contract; a later packer may compact it into a single runtime resource pack without changing its logical organization.

This repository must **never publish the ROM, ripped CHR graphics, generated palettes/screens, proprietary asset packs, frame captures or saved games**. Shipping original copyrighted artwork/audio requires appropriate rights or a user-side import workflow. Merely extracting bytes does not establish redistribution rights.

## Current extractor command

Run in a checkout with the exact Japanese ROM at the specified path:

```powershell
py -3.12 tools/extract/export_content_v1.py `
  --rom 'C:\NESDev\AkumajouDensetsu\Akumajou Densetsu (Japan).nes' `
  --out 'data/generated/jp-rom-content-v1'
```

The tool refuses an existing destination. Never force overwrite: archive or explicitly move a prior evidence build first.

## Acceptance levels

1. **Decoded ROM-local:** parser, tables, offsets, checksums and stage/room IDs match the authenticated ROM — current scope.
2. **ROM transition-verified:** all world positions, graph edges and animation/collision semantics derive from validated ROM writes or instructions — pending.
3. **Render-matched:** independent original-game captures match the native renderer, including CHR bank phase, palettes, camera, sprites, and HUD — pending.
4. **Game-complete:** repeatable all-route gameplay, audio, persistence and high-resolution presentation acceptance — pending.

No self-referential W8–W13 screenshot assembly may be used as the independent reference.
